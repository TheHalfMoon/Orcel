# SG-000115 preparation: browser host launch on macOS and Linux (XP-14)

**Status: PREPARATION ONLY.** This packet is not an activation. It grants
no authority, changes no spec state, and adds no capability. SG-000115
becomes active only through the SpecGrain process: an activation spec in
`.specgrain/specs/`, its own reviewed PR, and the founder's decision.
Until then, browser launch on macOS and Linux stays refused (the
`worker_launch.rs` fallback starts nothing, and the non-Windows
managed-policy check returns `Unreadable`, which fails closed).

Backlog entry: `IMPLEMENTATION_BACKLOG.md` → XP-14. Roadmap phase: X4.

## Objective

Bring the SG-000074..79 / SG-000108 browser host guarantees to macOS and
Linux. The host finds and verifies an installed Chrome or Edge, launches it
over the pipe with host-built argv, confines its network, supervises and
sweeps its process tree and profile, and the browser tools keep the same
policies on all three OSes.

**Authority delta (when activated):** the existing browser authority on two
more OSes. No new capability, tool, MCP shape or approval class.

**Decision.** The founder's message "ORCEL — FOUNDER DECISION: SG-000115 PRE-ACTIVATION ENGINEERING" (2026-10-29, sent in the implementing session; this amendment's PR #526 is its durable record) authorized "the preparation and implementation of SG-000115's remaining authority-neutral, unexposed components before activation". The decision says this is "explicit founder authorization for preparatory engineering, not authorization to activate SG-000115 or enable browser launching on macOS or Linux". It is not an activation. SG-000115 stays inactive, no activation spec exists, and nothing here grants authority.

The work falls into three categories.

### A. Inert engineering: may be prepared before activation

These six items, and only these, may be prepared before activation. Nothing elsewhere in this packet widens them. Code and tests for them are kept unexposed. They are referred to as A1 to A6:

1. macOS and Linux managed-policy inspection and fail-closed handling.
2. Process supervision and bounded descendant tracking.
3. Profile ownership, locking and symlink protection.
4. Network-confinement primitives and negative leak tests.
5. Shutdown, cleanup, recovery and crash regression tests.
6. Integration fixtures and test infrastructure.

A component counts as inert only when all of the following hold:
- **Build-time exclusion.** It is compiled only into test builds (`#[cfg(test)]`) or behind a never-default feature. `orcel-browser-host` stays out of every release build: orceld reaches it only through the never-default `live-browser-test` and `live-browser-dev` features. The release-blocker sweep (`crates/orcel-lifecycle/tests/release_blocker_sweep.rs`) is green at the exact head.
- **No production caller.** No launch path, orceld dispatch, MCP tool or release package reaches it.
- **Fail-closed behaviour, unchanged and pinned by tests:**
  - `engine_launch_admitted()` (`crates/orcel-browser-host/src/host.rs`) still refuses on macOS, and no new code path bypasses it or runs before it (`tests/sg000074_host.rs`);
  - the `worker_launch.rs` fallback starts nothing on macOS and Linux;
  - the managed-policy stub answers `Unreadable` off Windows.
- **No new or widened browser operation.** `apps/orcel-mcp/src/surface.test.ts`, `browser-exposure.test.ts` and `tool-contract.test.ts` pass unchanged at the exact head.
- **Source scan.** A test pins that only the component's own module and tests name it.
- **Test processes.** Inert tests may spawn only fixture or fake child processes. Starting a real Chrome or Edge on macOS or Linux, even on CI, is category B.
- **Windows unchanged.** Windows behaviour is unchanged.

Each slice still needs:
- its own PR;
- an independent security review;
- negative tests;
- exact-head CI, including Windows non-regression.

A slice that meets every condition above and passes all its gates may be merged. A slice that cannot meet them is left as a Draft PR and stays unmerged.

## Remaining slices (each its own qualified PR)

Before activation, only what category A above allows may be prepared. Each slice below is tagged with its category:
- **Remaining slice 1 (launch argv):** category B. At most a pure argv-builder helper compiled only into tests counts as category A, as part of A4 (network-confinement primitives).
- **Remaining slice 2 (managed policy):** category A for the read-only reader (A1). Category B for replacing the `Unreadable` stub or wiring the reader into launch.
- **Remaining slices 3 and 4 (supervision, profile hold):** category A (A2, A3), with fixture processes only.
- **Remaining slice 5 (network-leak probes):** category A for the probe primitives and negative tests against fixture endpoints (A4). Category B for running them against a real engine.
- **Remaining slice 6 (E2E):** category B. Its fixtures and test infrastructure fall under A6.

1. **Launch argv on Unix.** `build_worker_argv` takes the proxy as a
   parameter: the sink's URL on macOS and Linux, `NO_ROUTE_PROXY` on
   Windows (unchanged). `assert_worker_argv_exact` compares against the
   same host-built value, including the `<-loopback>` bypass entry that
   removes Chrome's implicit direct route to loopback. The sink outlives
   the engine: it is stopped only after the teardown sweep has confirmed
   that every engine process exited, because a stopped sink frees its port
   for another local process (the #501 contract).
2. **Managed-policy precondition on Unix.** This replaces the fail-closed
   `Unreadable` stub with real reads:
   - macOS: `/Library/Managed Preferences/` and the per-user managed
     preference domains for `com.google.Chrome` and `com.microsoft.Edge`.
   - Linux: `/etc/opt/chrome/policies/{managed,recommended}`,
     `/etc/opt/edge/policies/...`, and `/etc/chromium/policies/...`
     (discovery finds only Chrome and Edge; Chromium's directory is read
     because some distributions' Chrome builds read it too, and refusing
     on it only fails safe).
   - Present, populated or unreadable → refuse, as on Windows.
3. **Supervision.**
   - Linux: a new process group, `pidfd_open` for the main process, and
     `PR_SET_CHILD_SUBREAPER` so the engine's helpers cannot escape.
   - macOS: a process group plus kqueue `EVFILT_PROC` `NOTE_EXIT`.
   - Both sweep on teardown and confirm every engine process exited
     within the existing deadline. This is the counterpart of
     `terminate_and_confirm` (#497).
   - The sweep covers descendants, not only the group: a helper that
     calls `setsid`/`setpgid` leaves the group. On Linux the subreaper
     makes such processes the host's children, so the sweep lists and
     confirms the host's children too. macOS has no subreaper, so the
     sweep must track descendants (for example kqueue `NOTE_TRACK`,
     whose support must be checked, or a descendant walk), or the escape
     is recorded as a macOS residual risk.
4. **Profile hold.** Open the profile root and lock files with `O_NOFOLLOW`
   and `O_DIRECTORY`, check the owner and mode (0700), and keep the
   descriptors open across the lifetime. `leftovers.rs` gains a Unix sweep.
5. **Network-leak probes.** Port the native endpoint tests:
   - nothing reaches a local listener on port 9;
   - the sink's count is reported;
   - IP-literal navigation is blocked;
   - WebRTC sends no non-proxied UDP.
6. **E2E.** Run the SG-000108 PDF journey on hosted macOS and Ubuntu with
   Chrome installed.

## Security review (preparation)

| Risk | Treatment |
|---|---|
| S-06: `0.0.0.0` is loopback on Unix | Closed by the sink (#501) once slice 1 passes its port; never `0.0.0.0:9` off Windows. The `<-loopback>` bypass entry stays, so loopback is not reached directly either. |
| S-07: Linux verification is weaker (package-manager trust, no code signature) | Recorded residual risk; the activation must accept it explicitly or keep Linux refused. **Founder decision.** |
| Engine helpers escaping supervision (zygote, crashpad handler) | Subreaper (Linux) and process-group sweep; confirmation of every member's exit, as on Windows. |
| A helper leaves the process group (`setsid`/`setpgid`) | Linux: the subreaper adopts it and the sweep confirms the host's children. macOS: descendant tracking (kqueue `NOTE_TRACK`, support to be checked, or a descendant walk); otherwise a residual risk the founder must accept. |
| PID or process-group ID reuse on teardown | pidfd (Linux) and kqueue on the exact process (macOS) instead of bare PIDs; the group is never signalled after its leader exited and the group may have emptied. |
| Profile path swapped for a symlink | `O_NOFOLLOW` opens, owner and mode checks, descriptors held for the lifetime. |
| Managed browser policy overriding the confinement flags | Slice 2 refuses any present policy, as Windows does. |
| Proxy or `*_PROXY` environment inherited by the engine | The scrubbed launch environment (as on Windows) plus an exact argv; environment proxies are ignored when `--proxy-server` is set, and a test confirms it. |
| macOS TCC prompts during launch | The engine needs no TCC-protected access for headless automation. Any prompt is a test failure, never something to approve or pre-grant. |
| Sink port taken by another local process | While the sink runs its listener holds the port. The real window is after it stops, so it is stopped only after every engine process is confirmed gone (slice 1). |

## Tests to write (from the backlog, made concrete)

- **Positive:** engine found, verified and launched on hosted macOS and
  Ubuntu with Chrome; the PDF journey passes.
- **Negative:**
  - an unsigned or re-signed engine is refused (macOS);
  - an unowned or modified binary is refused (Linux);
  - a populated policy directory is refused;
  - a listener on port 9 receives zero bytes;
  - IP-literal navigation is blocked.
- **Recovery:** an engine crash leaves leftovers that the next start sweeps.
- **Teardown:** every process-group member is gone within the deadline,
  and nothing is left holding the profile.
