## Why this needs governance

SG-000108's acceptance binds the live browser surface:

- **A13:** "Any live tool is a subset of the twelve SG-000079
  `browser_structured` shapes; the exposure profile, discovery,
  documentation and OAuth scope tables change together." The live MCP set
  today is six tools (`page_open`, `navigate`, `observe`, `click`,
  `download_preview`, `download`; `crates/orcel-browser-host/src/exposure.rs`).
  - **Already inside the twelve, held model-only by SG-000108 decision 4:**
    `browser.dom/fill`, `browser.upload/preview` and
    `browser.upload/submit` (`QUALIFIED_BROWSER_SHAPES`). Making them live
    is a promotion within the twelve, governed by A7 and decision 4, not
    an A13 widening.
  - **Outside the twelve, so exposing them widens A13:** select, check,
    press, hover, text waits, dialog accept, tabs, frame observation and
    the verifier.
- **A7:** exposure, discovery, documentation and OAuth scope tables must
  agree mechanically for any tool added, and remote mapping stays
  disabled.
- **A4:** frames, popups and workers obey the SG-000075 rules;
  `navigation::mediate_frame` (and `mediate_popup`, which calls it) allow
  the exact same origin only. BR-05 tabs (admitting a popup as a new tab)
  and any observation of **cross-origin** frames (E4) both relax that part
  of the acceptance.
- **BR-04 step 1** (an interactivity flag in observations) changes the
  observation contract that clients rely on.

## Security review (preparation)

| Risk | Treatment |
|---|---|
| Upload as data exfiltration | One host-staged file per approval, bound to the page origin, the form's submission target origin, and the file's name, type and SHA-256 (all shown to the person); a submission to any other origin is refused; the worker never sees a workspace path; STRONG for sensitive workspaces |
| Form fill of secrets into a hostile page | SOFT approval shows origin, element role and name and a value digest. **Open design question:** how a value is classified as secret (a value taken from the XP-19 secret store would be refused by provenance; free text has no reliable classifier). The activation spec must settle it |
| `press` causing an unapproved submission | A key press that submits or navigates is approved as that submission or navigation, with its target origin |
| Approval replay across pages or elements | The digest binds page generation, element identity (role and name, BR-01) and value; stale references are refused, never retargeted silently |
| Dialog spoofing (a page drawing a fake dialog) | Only engine-reported JavaScript dialogs are answerable; their text digest is in the approval |
| A `prompt()` answer as egress | The answer's digest is part of the approval; an answer other than the approved one is refused |
| Popup and tab admission widening navigation | Popups to non-admitted origins stay closed; admitted ones inherit the lifetime's pins and SG-000075 rules; host-issued tab ids |
| Cross-origin frame content leaking | Same-origin frames only unless the founder admits cross-origin observation (an A4 change); then only frames whose origin is admitted, with the same redaction as the main document |
| Clickjacking or covered targets | BR-04 refusal of covered targets stays in force for every pointer action |
| Contract drift between tables | A7's mechanical agreement test runs for each added tool |
| Remote reach | Remote mapping stays disabled; local-only, as SG-000108 |

## Tests to write (per slice)

- Each tool appears in the exposure profile, discovery, documentation and
  OAuth scope tables together, or in none (A7).
- An approval is refused when replayed on another page generation,
  element or value.
- An upload of anything but the staged file is refused; the worker never
  receives a workspace path.
- Dialog accept without approval is refused, and default dismiss is
  unchanged.
- A popup to a non-admitted origin is closed; an admitted popup tab keeps
  the pins (E6).
- The native suite (SG-000108 fixtures) passes with each slice, Windows.

## Recommended first activation (narrow)

**Proposal, not an activation.** Today an agent can open, read, click same-origin links and download, but cannot fill in a form. The smallest step that makes the browser useful for real work is **forms on admitted pages**, nothing else:

| Included | Slice | Why | Approval |
|---|---|---|---|
| Fill a text field | E1a | Promotion within the twelve shapes. Fields that **look** secret by their type, autocomplete, name or id are already refused (`isSecretField`). A secret typed into a field named `notes` is **not** detected, so this packet's open question stays open: the activation spec must say what the person is told | SOFT. Today's prompt shows a digest; showing the value is new work with rules for long values and control characters, because the approval binds text a dialog may cut off |
| Select, check | E1b | The rest of an ordinary form | SOFT per action |
| Press Enter | E1b | The way to submit. Today's `press` accepts any listed key on any element and only refuses Enter in a multi-line field, so an Enter-only, single-line limit is **new checks** | SOFT, stating that the page may submit or send what it holds. **The effect can't be known before the key**: a script can change the form's action or move focus. So enforcement is the route rule (one admitted destination per lifetime), and any origin shown is an unbound snapshot |
| Wait for text | E1b | Observation: the agent can tell the page changed | None |
| Postcondition verifier | E5 | Read-only: the agent checks its own result | None |

**Deferred:** other keys and hover, uploads (egress, E2), dialog accept (E3), frame observation (E4), tabs and popups (E6, which reverses A4) and the interactivity flag (E7). None of these is needed for forms on one admitted page.

**Unchanged:**
- `orceld` stays the sole approval and execution authority. Each action is approved one at a time, bound to the page generation, element and value.
- Local only: remote mapping stays disabled.
- Windows only until SG-000115 is activated.
- **Development builds only** until F4 slice 7 is decided. So this makes the browser usable for development and evaluation first.

**What it widens:** SG-000108 A13 (select, check, press, waits and the verifier are new shapes) and decision 4, which holds fill model-only. That is why it needs activation. A4 is untouched.

**A consequence to accept:** a page's own script can read a filled value and send it to its admitted origin without any submit. Approving a fill means trusting that page with that value.

**Cost:** none. **Reversible:** yes, the tools can be removed from the profile tables. **Not qualified:** no agent has driven these through orceld. The host and worker actions pass their native tests, but the orceld dispatch and MCP tools don't exist yet.
