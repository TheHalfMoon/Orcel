## Security review (preparation)

| Risk | Treatment |
|---|---|
| Upload as data exfiltration | One host-staged file per approval, bound to the page origin, the form's submission target origin, and the file's name, type and SHA-256 (all shown to the person); a submission to any other origin is refused; the worker never sees a workspace path; STRONG for sensitive workspaces |

| Dialog spoofing (a page drawing a fake dialog) | Only engine-reported JavaScript dialogs are answerable; their text digest is in the approval |

## Slice A6: Enter's route and the native run

**Merged: #769 → `da046b82`.** The record of the change is `docs/security/SG-000108_PRODUCT_CALLER.md`, "SG-000122 slice A6". In short:

- An approved Enter may open one top-level document, a GET or POST on the page's committed origin, once, with redirects that stay on it (the Enter route rule, the spec's "enforcement is the route rule"). That document becomes the page's next generation, and the reply says `navigation: document_committed`.
- An Enter that opens nothing says `navigation: none`.
- Anything that would leave the origin before the admitted document opened (the form's action, a page script, a frame or a popup) is refused before it leaves and answers `CAPABILITY_DENIED` (journaled `failed`). Once the admitted same-origin document has opened, the submission has been delivered and the server may have acted: a refusal after that (a server redirect off the origin, a second document) or any failure answers outcome unknown (journaled `unknown`), never "refused". Nothing reaches another origin either way, and the page must be navigated again.
- After an Enter that committed no document, and after a committed Enter during which a frame or popup, or a redirect after the document opened, was refused, the host keeps the no-document rule in force until the next successful observation, an approved navigation (or an approved activation, WebMCP submission or download whose approval was consumed), or an approved Enter that commits cleanly. So a submission the page starts late, or a popup that outlives the Enter, is refused.
- An Enter is committed only at the URL the host admitted for its document: the document request's URL, or the target of its last main-frame document redirect (the worker marks those hops; a subresource's, frame's or popup's redirect never moves it), a fragment aside.
- Fill, select and check keep BR-02's no-new-document rule.
- The native run is part of `npm run browser-launcher:native`, which Windows CI requires. It covers the journey through orceld under the real broker and ledger, and the host-level route cases. **The consent is scripted** (the tests' decider approves each prompt and keeps what it showed), so CI proves the mechanism, not a person's approval.
- **What the native run has shown so far.** On GitHub's Windows runner (CI run 43754108084, head `885fe42f`), the host's `sg122_an_enter_submits_once_on_its_origin_and_never_leaves_it` drove Edge and passed: a same-origin POST and a GET committed as new generations, the form's action and a script leaving the origin were refused before leaving, a delivered POST whose redirect left the origin answered outcome unknown, and nothing reached `other.test`. The runner carries a managed Edge policy, so the worker-host `sg122_form_actions_go_through_bound_approvals_and_the_host_refuses_the_rest` and orceld's `sg122_the_form_journey_runs_under_the_broker_with_recorded_decisions` stopped at the managed-policy refusal (`SG108-EVIDENCE ... managed policy present; open refused typed`), as every SG-000108 lifetime test does there. A local run on the development PC (no managed policy) was refused earlier: its Edge had updated to 157, and the host qualifies Edge 155 and 156 only (`QUALIFIED_WORKER_ENGINES`). So the full form journey through orceld has not yet driven a real engine; that needs a machine with a qualified Edge and no managed policy, or Edge 157 qualified by its own PR. The founder-present run needs the same.
- **Edge 157, after the closeout (2026-11-16).** #771 (merge `b155d948`) qualified Edge 157 for the worker, with two Edge features disabled in the argv (`SG-000108_ENGINE_ATTACHMENT_DECISION.md`). On Edge 157 on the founder's PC (no managed policy), the native run then drove the full SG-000122 form journey through orceld and it passed under scripted consent: `SG122-EVIDENCE orceld live form journey: ... 12 decisions recorded`. The run skipped the three native tests that change the machine, so they are unverified on this PC. This is still scripted consent: it shows that the journey works on a real engine, not that a person approved it. The founder-present run below is still pending.
- **Denial attribution (branch `browser/denial-attribution`, after #771).** #771's judge found that the worker reported every `net::ERR_BLOCKED_BY_CLIENT` as Orcel's own route denial, although the engine uses the same error for its own cancellations (Edge 157's HTTPS-First auto-upgrade did, before #771 turned it off). The worker now records each refusal its route stack makes (`refusals.ts`) and reports "denied" only for a navigation failure that matches one of them. Any other failure is "failed", which the host maps to a failed or unknown outcome, never to success or a refusal. For an Enter, the host still decides the outcome from its own route record: refused, outcome unknown, or the worker's failure (outcome unknown).

### Known limits

- The ordinal is checked against the host's latest observation.
