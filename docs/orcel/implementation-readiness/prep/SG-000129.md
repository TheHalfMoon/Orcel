## 3. Security analysis

**Trust boundary.** The agent is a client. Everything it receives is
untrusted data, and everything it sends is a proposal. orceld authorizes,
executes, audits and verifies each call: its policy, approval broker, leases,
journal and protected surfaces are untouched. Nothing below relies on the
agent for orceld's safety. The agent-side rules are defence in depth and make
honest evaluation possible.

| # | Threat | Where it could come from | Control | Proof |
|---|---|---|---|---|
| T1 | **A second execution path** | DeerFlow's sandboxes, bash, file and browser tools; LangChain community tools; `langchain-mcp-adapters` opening its own session | No such module is imported. The M1 gate is the only holder of the edge session. LangChain tools are thin proposals that call the gate. | A source scan of `orcel_agent/**`: no subprocess other than the one allowlisted edge spawn, no shell, no socket, no `ClientSession` outside `edge.py`. A test that a tool the model invents is refused before dispatch. |
| T2 | **Approval or lease bypass** | A model that loops asking for approvals; a planner assuming a Full User lease | orceld's broker asks the person. The per-run approval budget (3) stops the run at the first denial. Mutating tools stay off the allowlist. Tests use a test orceld only. | The M1 budget and refusal-is-final tests, extended to the adapter. |
| T3 | **Replay after a crash or compaction** | Checkpoints restoring a pending call; summarization dropping the record of a dispatch | The resume invariant: a call dispatched but not recorded becomes `OUTCOME_UNKNOWN` and is never re-dispatched from agent state. The gate's journal, not the LangGraph checkpoint, decides. | Kill between dispatch and record, then resume from the checkpoint, at slices 4 and 5. |
| T4 | **Prompt injection** | File and UIA text, tool results, summaries and todos (the model writes these from tainted text) | A static system prompt. Untrusted content goes in the human or data channel. A summary or todo can't add a tool or widen an argument, because the gate checks every call against the edge's schemas and the allowlist. A clarification question is never consent. | Injected-instruction tasks at slice 6, and unit tests at slice 4. |
| T5 | **Telemetry and egress** | `langsmith` (pulled in by `langchain-core`), tracers, `tiktoken` BPE downloads, `httpx` in `mcp` | Tracing is forced off in-process, overriding the environment. `tiktoken` is not admitted: token counts use an approximate counter. No HTTP transport is used, only stdio. | Socket-denied import and run tests. A tracing-requested-but-off test. |
| T6 | **Unattended mutation** | Under a Full User lease, routine operations need no fresh approval | The allowlist stays read-only. Mutating tools need a read-only lease-state signal, a separately decided change. | The M1 allowlist tests. The excluded scope is in the spec. |
| T7 | **Leaks from agent state** | Checkpoints holding model context, which contains file and UIA text | Only the private per-run store. Owner-only: 0700 on Unix, and a **protected owner-only DACL on Windows**, which M1 recorded as owed to this grain. Size-capped, expiring, and deleted at the end of the run. No raw screenshots. orceld already redacts secrets. | Store tests at slice 5, including the Windows DACL. |
| T8 | **Supply chain** | About 60 transitive distributions; sdists running build code; typosquats | Wheels only (`--only-binary :all:`), `--require-hashes`, a resolved lock, a license table and an advisory audit. Install only into an isolated environment for the agent. Nothing in orceld, the edge or any shipped artifact depends on it. | Slice 1 CI on three OSes. A supply-chain review by the slice 1 judge. |
| T9 | **License and provenance** | Copied DeerFlow code | Each copied or adapted file names its DeerFlow path and the pin. The verbatim MIT text sits at `apps/orcel-agent/third_party/deer-flow/LICENSE`. A provenance ledger maps file → source blob → changes. The donor lock gains each slice's closure. Nothing DeerFlow-branded is user-facing. | A ledger-completeness test from slice 1 on. |
| T10 | **Over-claiming** | Scripted runs reported as model performance | Every row is labelled `deterministic-scripted`. Autonomous rows need M4. | The report schema rejects an unlabelled row. |

**Residual risks, recorded rather than accepted silently:**
- **LangChain and LangGraph churn quickly.** A pinned lock and a pure rollback
  (the agent sits above the edge) bound the impact.
- **`langchain-core` imports `langsmith`, even with tracing off.** The
  egress-denied tests are the guard, not trust in configuration.
- **Windows Python cannot apply a protected DACL with the standard library
  alone.** Slice 5 must either do it with `ctypes` against advapi32, which is
  allowed (no new dependency, no subprocess), or stop and record the gap for
  review. Inheriting the root's ACL is not accepted as the closing state.

## 4. Dependency admission (slice 1)

**Starting versions.** These are what the DeerFlow pin resolves in
`backend/uv.lock`, which the copied middlewares were tested against:

| Package | Pin version | License (PyPI metadata) |
|---|---|---|
| langchain | 1.3.14 | MIT |
| langchain-core | 1.4.9 | MIT |
| langgraph | 1.2.9 | MIT |
| langgraph-checkpoint | 4.3.0 | MIT |
| langgraph-checkpoint-sqlite | 3.1.2 | MIT |
| langgraph-prebuilt | 1.1.0 | MIT |
| mcp | 1.30.0 | MIT |
| langchain-mcp-adapters | 0.2.2 | MIT |
| pydantic | 2.13.3 | MIT |

PyPI's newer releases (for example langchain 1.4.7 and mcp 2.3.0, checked
2026-10-30) are not adopted by default: a major version of `mcp` or a minor
version of `langchain` could change the built-ins the copied code subclasses.

**Procedure:**
1. Resolve the transitive closure for Python 3.12 on the three CI OSes into
   `apps/orcel-agent/requirements.lock`, with a SHA-256 for every wheel.
2. Install with
   `pip install --require-hashes --only-binary :all: --no-deps -r requirements.lock`
   into a fresh virtual environment, on CI and in local development.
3. Generate `apps/orcel-agent/THIRD_PARTY_LICENSES.md` from the installed
   metadata. Admitted licenses are MIT, BSD-2/3-Clause, Apache-2.0, PSF-2.0
   and ISC. Anything else blocks until it is recorded and reviewed.
4. Run an advisory audit (`pip-audit` against the free OSV/PyPI databases) in
   CI. Any advisory must be fixed by a recorded version move, or recorded and
   reviewed.
5. Do not admit `tiktoken` or any provider SDK (`langchain-openai`, Anthropic,
   Ollama and similar). LangChain's in-process fake chat models are the only
   models in M2 and M3.
6. Force LangSmith off in the agent's entry point (`LANGSMITH_TRACING`,
   `LANGCHAIN_TRACING_V2` and tracer callbacks), regardless of the
   environment.

Network use is limited to downloading the locked wheels from PyPI while
installing, on CI and in development. That costs nothing. No model,
tokenizer or other runtime asset is downloaded.

## 6. Acceptance tests

These are the spec's `acceptance`, with the concrete tests each slice must
add:

- **Slice 1:**
  - lock install on three OSes;
  - license-table completeness and allowlist;
  - advisory audit;
  - import with sockets denied;
  - LangSmith off when `LANGSMITH_TRACING=true` is set;
  - ledger completeness;
  - the verbatim MIT text, checked by hash.
- **Slice 2:**
  - a fake chat model reproduces Tier A through the real edge and a test
    orceld, with the calls, refusals and audit records matching M1;
  - the gate refuses, before dispatch:
    - an invented tool;
    - a tool outside the allowlist;
    - schema-invalid arguments;
    - a fourth approval-bearing call;
    - a call after a denial;
  - a scan shows exactly one session holder.
- **Slice 3:** the ported loop-detection suite, plus a loop trap through the
  real edge that stops at the hard limit with the decision recorded.
- **Slice 4:**
  - the ported todo, summarization, budget, error and dangling-call suites;
  - injected instructions in a file survive into a summary or todo and still
    cannot widen a call;
  - an oversized UIA or directory result is budgeted in memory or in the
    private store;
  - a dangling call across a compaction is still `OUTCOME_UNKNOWN`.
- **Slice 5:**
  - kill and resume from the checkpoint yields `OUTCOME_UNKNOWN` and a
    re-observation, never a re-dispatch;
  - checkpoint location, size cap, TTL and deletion;
  - 0700 on Unix and a protected owner-only DACL on Windows.
- **Slice 6:** the report. It compares M2/M3 with M1 on BM-02 Tier A and the
  synthetic tasks, and records:
  - success;
  - calls and refusals;
  - approval requests;
  - p50 and p95 step and task time;
  - peak RSS;
  - context size over steps;
  - loop and compaction events;
  - resume outcomes;
  - security failures.

  Every row is labelled `deterministic-scripted`.
- **Every slice:**
  - the M1 tests, the source scan and the egress test still pass;
  - the agent is unpackaged and unreferenced by orceld;
  - exact-head CI on three OSes;
  - a fresh-context security judge;
  - d1-local only as an advisory.
