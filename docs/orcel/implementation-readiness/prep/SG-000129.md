## 1. Founder decision

On 2026-10-30 the founder gave the implementing session a directive in chat.
It is quoted verbatim on #536 and in the spec's `decisions`. It does three
things:

- **It authorizes the activation process.** "You are authorized to initiate
  the formal SpecGrain activation process for: Orcel Agent — Core-integration
  planner (DeerFlow-derived MCP client)". It requires the specification,
  security analysis, dependency admission, acceptance tests and independent
  review. It says "Do not treat this instruction alone as a completed
  SpecGrain activation."
- **It authorizes implementation once the gates are met.** "Prioritize M2
  and M3 once their governance requirements are satisfied." and "Once the
  required governance gates are satisfied, begin the first executable M2
  implementation immediately." It lists the items to implement or
  transplant. This is the same structure as SG-000128's decision ("the
  formal SpecGrain activation process and implementation … subject to all
  required governance"). The directive also says "Continue without routine
  confirmation requests.", so no second approval is sought.
- **It sets boundaries,** quoted verbatim in the spec:
  - an unprivileged MCP client, with orceld the sole execution and approval
    authority;
  - no DeerFlow host-shell tools, alternative computer-control paths, cloud
    sandbox backends or other privileged mechanisms;
  - unexposed and unshipped;
  - "No runtime skill installation, unexpected network egress, approval
    bypass, or Full User lease assumptions.";
  - no model inference or downloads before the model-selection and licensing
    gates.

The founder's instruction is the decision. The packet does not count it as
the activation: activation happens when the repository's governance
requirements are met. Those requirements follow SG-000128 (#515, activation
commit `3b5bfd6a`):
1. the founder decision, recorded on a planning issue;
2. a spec in `.specgrain/specs/`;
3. rule changes recorded before implementation and pinned in tests;
4. `docs/canonical/CURRENT.md` recording the activation and the decision;
5. a fresh-context independent review with every finding resolved;
6. exact-head CI and a normal merge;
7. green post-merge CI.

**Not decided by this grain, and still pending:**

## 3. Security analysis

**Trust boundary.** The agent is a client. Everything it receives is
untrusted data, and everything it sends is a proposal. orceld authorizes,
executes, audits and verifies each call: its policy, approval broker, leases,
journal and protected surfaces are untouched. Nothing below relies on the
agent for orceld's safety. The agent-side rules are defence in depth and make
honest evaluation possible.

| # | Threat | Where it could come from | Control | Proof |
|---|---|---|---|---|
| T1 | **A second execution path** | DeerFlow's sandboxes, bash, file and browser tools; LangChain community tools; an MCP library opening its own session | No such module is imported. `mcp` and `langchain-mcp-adapters` are not admitted. The M1 stdlib client is the only edge session. LangChain tools are thin proposals that call the gate. | The source scan grows only by named imports, and gains a denylist that is never narrowed (spec decision): `mcp.client`, `mcp.server`, the adapters' client and sessions, `ClientSession`, `stdio_client`, `langchain_community`, provider SDKs, `subprocess` outside `edge.py`, `socket`, `urllib`, `http.client`, `enable_load_extension`. A tool the model invents is refused before dispatch. |
| T2 | **Approval or lease bypass** | A model that loops asking for approvals; a planner assuming a Full User lease | orceld's broker asks the person. The per-run approval budget (3) stops the run at the first denial. The entry point refuses any allowlist that is not a subset of the M1 read-only set. Every real-orceld run starts from a fresh, empty test state root and asserts that no lease exists. | The M1 budget and refusal-is-final tests, extended to the adapter. An allowlist-subset test. A no-lease assertion in slices 2 and 6. |
| T3 | **Replay after a crash or compaction** | Checkpoints restoring a pending call (LangGraph re-runs pending ToolNode writes on resume); summarization dropping the record of a dispatch | The resume invariant. A call dispatched but not recorded becomes `OUTCOME_UNKNOWN` and is never re-dispatched from agent state. The gate's journal, not the LangGraph checkpoint, decides. Resuming drops pending tool-call writes. | Slice 5 has two tests. (a) A resume drops pending writes. (b) A kill between dispatch and record, with a **test-only mutating tool on a fake edge** (with a read-only allowlist alone, a repeat read would pass vacuously), yields `OUTCOME_UNKNOWN` and no re-dispatch. Slice 4 tests the same across a compaction. |
| T4 | **Prompt injection** | File and UIA text, tool results, summaries and todos (the model writes these from tainted text) | A static system prompt. Untrusted content goes in the human or data channel. A summary or todo can't add a tool or widen an argument, because the gate checks every call against the edge's schemas and the allowlist. A clarification question is never consent. | Injected-instruction tasks at slice 6, and unit tests at slice 4. |
| T5 | **Telemetry and egress** | `langsmith` (pulled in by `langchain-core`), OpenTelemetry, `tiktoken` BPE downloads | The entry point sets every tracer variable off **before** any LangChain import: `LANGSMITH_TRACING`, `LANGCHAIN_TRACING_V2`, `LANGCHAIN_TRACING`; endpoints and API keys cleared; `OTEL_SDK_DISABLED`, `OTEL_TRACES_EXPORTER=none`. `tiktoken` is not admitted: token counts use an approximate counter. The only transport is stdio. | A `sys.addaudithook` installed before any import refuses `socket.connect`, `getaddrinfo` and `gethostbyname`. On the Linux leg, tests also run in a network namespace with no route (`sudo unshare -n`); the leg fails if it can't. A test that tracing stays off when the environment requests it. |
| T6 | **Unattended mutation** | Under a Full User lease, routine operations need no fresh approval | The allowlist stays read-only. Mutating tools need a read-only lease-state signal, a separately decided change. | The allowlist-subset test. The excluded scope is in the spec. |
| T7 | **Leaks from agent state** | Checkpoints holding model context, including tool results and so file and UIA text: a **recorded widening** of M1's journal-only store | Only the private per-run store. Everything stays inside the run directory and within the size cap: the database and every SQLite sidecar (`-wal`, `-shm`, `-journal`). `temp_store=MEMORY`, `secure_delete` on, no extensions. The cap is enforced inside SQLite (`max_page_count`, `journal_size_limit`, a WAL checkpoint and a capacity check before each save), so filling past it fails closed. Deleted when the run ends. A crash-kept directory expires under the 24-hour TTL, the accepted window, recorded. Owner-only **from creation**: 0700 on Unix; on Windows, `CreateDirectoryW` with a protected (inheritance-off), owner-only security descriptor, which closes the race of a DACL applied after `mkdir`. No raw screenshots. orceld already redacts secrets. | Slice 5 store tests: sidecar location and cap, temp store, deletion and expiry. On Windows, DACL protection and the absence of any broad principal. |
| T8 | **Supply chain** | The transitive distributions; sdists running build code; typosquats; native extensions | Wheels only (`--only-binary :all:`), `--require-hashes`, `--no-deps` on a resolved lock. A license table and a hash-pinned advisory audit (`pip-audit` from its own lock). Install only into an isolated environment for the agent. A native SQLite extension (for example `sqlite-vec`) is excluded or never loaded. Nothing in orceld, the edge or any shipped artifact depends on it. | Slice 1 CI on three OSes. A supply-chain review by the slice 1 judge. |
| T9 | **License and provenance** | Copied DeerFlow code; dependency licenses | Each copied or adapted file names its DeerFlow path and the pin. The verbatim MIT text sits at `apps/orcel-agent/third_party/deer-flow/LICENSE`. A provenance ledger maps file → source blob → changes. The donor lock gains each slice's closure. Nothing DeerFlow-branded is user-facing. Non-permissive dependency licenses are recorded exceptions (section 4). | A ledger-completeness test and a license-table test from slice 1 on. |
| T10 | **Over-claiming** | Scripted runs reported as model performance | Every row is labelled `deterministic-scripted`. Autonomous rows need M4. | The report schema rejects an unlabelled row. |

**Residual risks, recorded rather than accepted silently:**
- **LangChain and LangGraph churn quickly.** A pinned lock and a pure rollback
  (the agent sits above the edge) bound the impact.
- **`langchain-core` imports `langsmith`, even with tracing off.** The audit
  hook and the network namespace are the guard, not trust in configuration.
- **Plaintext model context may sit on disk for up to 24 hours after a
  crash,** in an owner-only directory. This is the recorded window. A later
  change may shorten it, but slice 5 may not lengthen it.
- **The Windows protected DACL needs `ctypes` against advapi32 and
  kernel32.** This is no new dependency and no subprocess, and is confined to
  one named module that calls only named functions, pinned by the scan. If slice 5 cannot do it, it stops and records the gap for
  review: inheriting the root's ACL is not accepted as the closing state.

## 4. Dependency admission (slice 1)

**Starting versions.** These are what the DeerFlow pin resolves in
`backend/uv.lock`, which the copied middlewares were tested against:

| Package | Pin version | License (PyPI metadata) | Slice 1 |
|---|---|---|---|
| langchain | 1.3.14 | MIT | admitted |
| langchain-core | 1.4.9 | MIT | admitted |
| langgraph | 1.2.9 | MIT | admitted |
| langgraph-checkpoint | 4.3.0 | MIT | admitted |
| langgraph-checkpoint-sqlite | 3.1.2 | MIT | admitted |
| langgraph-prebuilt | 1.1.0 | MIT | admitted (pulled in by langgraph) |
| pydantic | 2.13.3 | MIT | admitted |
| mcp | 1.30.0 | MIT | **not admitted.** It pulls a server and HTTP stack (starlette, uvicorn, httpx and more), and the M1 client keeps the session. |
| langchain-mcp-adapters | 0.2.2 | MIT | **not admitted.** It can't convert tools without its own session. |

PyPI's newer releases (for example langchain 1.4.7 and mcp 2.3.0, checked
2026-10-30) are not adopted by default: a newer `langchain` could change the
built-ins the copied code subclasses. A version moves only to fix a recorded
advisory or a test failure, and each move is noted in the lock.

**Licenses.**
- **The allowlist:** MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, PSF-2.0 and
  ISC.
- **Expected exceptions, recorded now and reviewed in slice 1 (not admitted
  by default):** `certifi` (MPL-2.0; used unmodified; MPL's copyleft is per
  file). Any other non-allowlisted license found while resolving blocks until
  it is recorded and reviewed.

**Procedure:**
1. Resolve the transitive closure for Python 3.12 on the three CI OSes into
   `apps/orcel-agent/requirements.lock`, with a SHA-256 for every wheel.
2. Install with
   `pip install --require-hashes --only-binary :all: --no-deps -r requirements.lock`
   into a fresh virtual environment, on CI and in local development.
3. Generate `apps/orcel-agent/THIRD_PARTY_LICENSES.md` from the installed
   metadata, and test that it covers every installed distribution.
4. Run `pip-audit`, installed from its own hash-pinned lock, against the free
   OSV/PyPI data. Fix any advisory by a recorded version move, or record and
   review it.
5. Admit no `tiktoken`, no provider SDK and no MCP library. LangChain's
   in-process fake chat models are the only models in M2 and M3.
6. Set the tracer variables off in the entry point before any LangChain
   import (section 3, T5).

**What is downloaded:** only the locked wheels (and `pip-audit`'s), from PyPI
while installing, on CI and in development. That costs nothing. No model,
tokenizer or other runtime asset is downloaded.

## 6. Acceptance tests

These are the spec's `acceptance`, with the concrete tests each slice must
add:

- **Slice 1:**
  - lock install on three OSes;
  - license-table completeness, the allowlist and recorded exceptions;
  - the hash-pinned advisory audit;
  - import under the audit hook, with no connection and no name lookup;
  - tracing off when `LANGSMITH_TRACING=true` and the OpenTelemetry variables
    ask for it;
  - none of `tiktoken`, provider SDKs, `mcp` or `langchain-mcp-adapters`
    installed;
  - ledger completeness;
  - the verbatim MIT text, checked by hash.
- **Slice 2:**
  - a fake chat model reproduces Tier A through the real edge and a fresh
    test orceld (no lease, asserted), with the calls, refusals and audit
    records matching M1;
  - the gate refuses, before dispatch:
    - an invented tool;
    - a tool outside the allowlist;
    - schema-invalid arguments;
    - a fourth approval-bearing call;
    - a call after a denial;
  - the entry point refuses an allowlist that is not a subset of the
    read-only set;
  - the extended source scan and its denylist pass.
- **Slice 3:** the ported loop-detection suite, plus a loop trap through the
  real edge that stops at the hard limit with the decision recorded.
- **Slice 4:**
  - the ported todo, summarization, budget, error and dangling-call suites;
  - injected instructions in a file survive into a summary or todo and still
    cannot widen a call;
  - an oversized UIA or directory result is budgeted in memory or in the
    private store;
  - a dangling call across a compaction is still `OUTCOME_UNKNOWN`.
- **Slice 5:**
  - a resume drops pending tool-call writes;
  - a kill and resume with a test-only mutating tool on a fake edge gives
    `OUTCOME_UNKNOWN` and no re-dispatch;
  - with the real edge, a re-observation comes before any further proposal;
  - the database and its sidecars stay in the run directory and within the
    cap, and filling past the cap fails closed;
  - `temp_store=MEMORY`, no extension loaded, expiry and deletion;
  - 0700 on Unix; on Windows, a protected owner-only DACL from creation.
- **Slice 6:** the report, against a fresh test orceld with no lease
  (asserted). It compares M2/M3 with M1 on BM-02 Tier A and the synthetic
  tasks (loop trap, long context, oversized output, injected instructions,
  kill and resume), and records:
  - success;
  - calls and refusals;
  - approval requests;
  - p50 and p95 step and task time;
  - peak RSS;
  - context size over steps;
  - loop and compaction events;
  - resume outcomes;
  - security failures.

  Every row is labelled `deterministic-scripted`.
- **Every slice:**
  - the M1 tests, the source scan and the egress test still pass;
  - the agent is unpackaged and unreferenced by orceld;
  - exact-head CI on three OSes;
  - a fresh-context security judge;
  - d1-local only as an advisory.
