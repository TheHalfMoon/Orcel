## The existing fixture is not a starting point

`tests/native-fixtures/apps/cross-platform/tauri/` is Cua's native test harness, imported unmodified under XP-08 (`0c090c41`) and built by no CI job. It is consistent with "no Vite, no Tauri CLI, no React": it builds with plain `cargo build --release --features custom-protocol`, and its `package.json` only wraps cargo. That is useful evidence that a CLI-free Tauri 2 build works. It must not be copied as the Control Room base, because it conflicts with this grain's authority boundary:

- `"csp": null`: no Content Security Policy at all.
- It starts a `tiny_http` server on `127.0.0.1:0` and loads `WebviewUrl::External("http://127.0.0.1:<port>/")`. That is a listener, and content loaded over HTTP rather than embedded assets.
- `js_init_script` injects an environment variable's value into every page.
- `tauri = "2"` and `tauri-build = "2"` are unpinned, there is no `Cargo.lock`, and default features (including dynamic ACL and compression) are on.
- No capability files, so no command allowlist is expressed.
- `"$schema": "https://schema.tauri.app/config/2"` is a remote URL (editor-only, harmless, but the Control Room config will not carry it).

The fixture stays a cua-driver test target and is not changed by this grain.

## Authority boundary

**orceld remains the sole security and authorization authority.** The Control Room is a viewer. Authority delta: none. The UI performs no browser, filesystem, shell or privileged action, directly or through a plugin.

### How it reads state

The Tauri Rust process (not the web view) is the only app API client. It opens this user's endpoint exactly as `ORCEL_APP_API_1.md` section 7 asks:

- **Endpoint, fixed.** `\\.\pipe\orcel-<user SID>-app`, derived from the process token's SID only. No environment variable (including `ORCEL_APP_API_INSTANCE`), argument or configuration file can change it. The A1 crate takes an instance suffix only through a constructor its own `#[cfg(test)]` tests use, so tests can reach a side-by-side orceld; the shell binary has no such path.
- **Identification-only open.** `CreateFileW` with `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION`, so orceld can identify the client but never act as it. orceld's `describe_holder` (`crates/orceld/src/app_api.rs`) already does this open.
- **Server identity before the first write.** Read `GetNamedPipeServerProcessId`; open that process with `PROCESS_QUERY_LIMITED_INFORMATION`; open its token with `TOKEN_QUERY`; require `TokenUser` to equal this process's user **and** the `TokenIntegrityLevel` label's last sub-authority to be at least `0x2000` (Medium). orceld's `describe_holder` and `token_user` compare the **account only**, so the integrity half is ported from the WPF preview's `ServerIsThisUser` and `ProcessRunsAsThisUser` (`apps/orcel-desktop-preview/src/Program.cs`, called at line 447, defined at lines 482-510). Any failure (no pid, `OpenProcess` refused, token unreadable, another account, below Medium) refuses the connection before a byte is written, and the window says "orceld could not be confirmed as yours". The pipe object is checked too, against a server that passed the process check and then handed the pipe on: `GetSecurityInfo(SE_KERNEL_OBJECT, OWNER_SECURITY_INFORMATION | LABEL_SECURITY_INFORMATION)` must show this user as owner (or, only when the client's own token is elevated, exactly BUILTIN\Administrators `S-1-5-32-544`, which owns what an elevated token creates) and a mandatory label of Medium or above (orceld labels its pipe `ME`); an unlabeled pipe, another owner, a lower label or an unreadable descriptor refuses, before any write.
- **Methods:** `status.get`, `capabilities.get`, `events.subscribe`, `task.list` and `task.get` (decision 5), as a closed Rust enum, so an unlisted name cannot be serialized, let alone sent. `task.stop`, `approval.history`, `clients.list` and every name orceld answers `UNKNOWN_METHOD` are absent.
- **Frames:** at most 64 KiB per frame, newline included; epoch-aware cursors; a gap is rejected before the cursor moves; a new epoch clears the timeline.

### The sanitiser: nothing reaches the web view unshaped

Every answer and event is parsed into Rust types and re-serialized from them. Whatever is not named below is dropped and counted (the window shows "n fields withheld"), including any field or event kind orceld adds later.

**Text rule (all retained strings).** Replace C0 and C1 control characters, every Unicode format character (general category Cf, which covers the bidi controls U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069 and U+061C, and zero-width characters), and U+2028 and U+2029 with U+FFFD; then cap the length in characters as stated per field. The front end renders text only, so this is a second layer, not the only one.

**Identifier rule.** `task_id`, `workspace_id` and `run_id`: 1 to 128 characters of `[A-Za-z0-9_-]`; `step_id`: `s` followed by 1 to 4 digits; `epoch`: orceld's real format `{pid:x}-{nanos:x}` (`new_epoch`, `crates/orceld/src/app_api.rs`), that is 1 to 8 lowercase hex digits, a hyphen, and 1 to 32 lowercase hex digits; the A1 test builds its cases from that format. A value that fails drops its whole record.

**Path rule.** Applied to exactly these fields: `folder`, `sources[].path`, `proposal.destination`, `report.destination` and `check.destination`. A path is shown only if it is workspace-relative: not empty, no drive letter, no leading `/` or `\`, no UNC or `\\?\` prefix, no `..` or `.` segment, no character the text rule would replace, no NUL, at most 1024 bytes. **File-name rule** for `proposal.name` and `report.name`: the path rule plus no `/` or `\`, at most 255 bytes. A field that fails is shown as "path withheld"; it is never shown, opened or resolved. The Control Room never joins a path to a workspace root, never touches the file system for it, and offers no "open file" or "reveal" action. A1 also refuses any `:` (a drive letter or an alternate data stream), any segment that is empty once trailing dots and spaces are trimmed (`...`, `. `, `.. `), Windows device names as a segment or file name (`CON`, `PRN`, `AUX`, `NUL`, `COM1`-`COM9`, `LPT1`-`LPT9`, with or without an extension, in any case), and characters that look like a separator or a dot (U+2215, U+2044, U+29F8, U+29F9, U+FF0F, U+FF3C, U+FE68, U+2216, U+FF0E, U+2024, U+FE52, U+3002, U+FF61).

**Hash rule.** `sha256` fields: exactly 64 lowercase hex characters, or withheld.

**Status (`status.get`, and the `status` inside a snapshot).** Kept: `name` and `version` (charset `[A-Za-z0-9._+-]`, at most 32), `internal_protocol_version` (same charset, at most 32), `app_api` (exactly `orcel-app-api/1`: its `/` is outside that charset), `read_only` (must be `true`; any other value makes the window show "incompatible orceld" and nothing else), `os` and `arch` (`[a-z0-9_]`, at most 16), `mode` (`[A-Za-z0-9_-]`, at most 32: orceld's real value is `SG-000039_CLIPBOARD_WRITE`), `policy_revision` (number or the identifier charset, at most 64), `started_at_ms`, `uptime_ms`, `events {epoch, head_seq, oldest_seq, ring_capacity}`, `clients {active, max}`, and from `endpoint_wait` only `since_ms` and `attempts`. Dropped: `pid`, `endpoint` (it carries the user's SID), `endpoint_wait.reason` (free text) and `peer`.

**Capabilities (`capabilities.get`).** Kept: `os`, `read_only` (must be `true`), and `capabilities[]` as `{id, state, reason}` with `id` in `[a-z0-9_.-]` (at most 64), `state` the closed enum `available` | `unavailable`, and `reason` text-ruled and capped at 200 characters (the explicit unavailable reasons CR-03 asks for). At most 64 entries. `methods` and `reserved_methods` are not forwarded.

**Events.** A closed allowlist of kinds, with fields per kind:

| Kind | Kept | Dropped or replaced |
|---|---|---|
| `daemon.started` | `mode` (as in status) | `pid` |
| `request.completed` | `capability` and `operation` (`[a-z0-9_.:/-]`, at most 64, or null: orceld sends null when a request had no shape, `request_event` in `crates/orceld/src/sg000039_main.rs`), `ok` (bool), `failure_code` (`[A-Z0-9_]`, at most 48, or null) | `request_id` |
| `app_api.endpoint_in_use` | the fact only, shown as "orceld waited for its endpoint" | `reason` (free text) |
| `task.updated` | `run_id` (identifier rule), `step_id`, `task_kind` (must be `report`), `state`, `step` and `outcome` (task enums below) | anything else |
| `snapshot` | `reason` (`gap` \| `epoch`), `head_seq`, `oldest_seq`, `status` (status rules), `resubscribe {after_seq, epoch}` | anything else |
| `{truncated: true, bytes}` data | shown as "event too large, withheld" | the rest |

Every event keeps `seq`, `epoch` and `at_ms`. Any other kind is dropped and counted. Heartbeats are consumed in Rust and not forwarded.

**Report tasks (`task.list`, `task.get`; decision 5).** orceld already reports paths workspace-relative (`report_task.rs`, `destination_of`), and its records hold paths, sizes, hashes, states and step outcomes, never file content. The sanitiser does not rely on that. Kept:

- `task_id`, `workspace_id` (identifier rule); `kind` (closed enum: `report`); `state` (closed enum: `observed`, `proposed`, `approval_denied`, `committing`, `verified`, `verification_failed`, `stale`, `failed`, `stopped`); `owner` (closed enum: `this_session`, `other_session`, `earlier_run`); `created_at_ms`, `updated_at_ms`.
- `folder`, `sources[]` as `{path, sha256, bytes}`, at most 64 sources; `proposal` and `report` as `{name, destination, sha256, bytes}`.
- `steps[]` as `{step_id, kind, outcome, at_ms}`, at most 32 steps (orceld's own cap), with `kind` and `outcome` as closed enums of the values orceld emits, enumerated in slice A1 from `crates/orceld/src/report_task.rs` and `crates/orceld/src/report_journal.rs` (the journal records the `reconcile` and `run`/`orceld_run_ended` steps) and pinned by a test against both files; a value outside them is shown as `other`, never as its text.
- from `check` only `checker` (closed enum: `orcel-report-check/1`; any other value drops `check`), `passed`, `destination`, `bytes`, `sha256`, `sources_unchanged`, `figures_confirmed` and `checked_at_ms`.
- At most 64 tasks in a list (orceld's `max_tasks`).
- **`title` is dropped entirely.** It is planner-written free text, which decision 5 does not list. Tasks are shown by state, destination and time.
- Excess sources, steps or tasks are dropped and counted. Report content, source content, secrets and any location outside a workspace never reach the UI.

### Pending approvals: nothing is shown yet

`ORCEL_APP_API_1.md` section 7 says a Control Room shows "waiting for approval on this device". But orcel-app-api/1 has no source of pending approvals: no status field, event kind or method names one, and `approval.history` (decisions already made) is outside this grain. So the window shows **nothing** about approvals until orceld exposes a read-only source, which needs its own change and decision. It never infers a pending approval from task states, and no control answers, cancels, dismisses or mints one. Nothing in this grain scripts, suppresses or bypasses a human approval prompt.

### Subscriptions

- **One live subscription per window.** A new `app_events` call first cancels the previous one (its orceld connection is closed and its Channel ends) and then opens one connection. A test calls `app_events` twice and sees one subscriber at orceld (`status.get` `clients.active`).
- **Bounded queue.** Frames waiting for the web view are held in a queue of at most 256. On overflow the queue is cleared, the orceld connection is closed, the web view receives a "gap" marker, and the client resubscribes from the last delivered cursor, so orceld answers with a snapshot when that cursor can no longer be served. Tested with a stalled consumer.
- **orceld's client limit.** orceld admits 8 concurrent clients. The window uses at most two connections: one subscription and one request at a time (requests are serialized). A second shell process is refused by a named mutex `Local\orcel-control-room-<user SID>`, created by the shell's own code (no single-instance plugin) with a DACL that grants this user only. `ERROR_ALREADY_EXISTS` means another instance of this user holds it: the second process exits with "Orcel Control Room is already open". `ERROR_ACCESS_DENIED` means the name exists under a DACL that refuses this user, so another account created it first (a squatter): the process exits with "another program holds the Control Room's name; it may be another account" and never opens a window. Each case is tested. Squatting the mutex name is recorded as a residual beside pipe squatting (below). A request while the subscription runs uses one more connection, never more.

### What the web view can call

Five Tauri commands and nothing else:

| Command | Argument | Answer |
|---|---|---|
| `app_status` | none | `status.get`, sanitised |
| `app_capabilities` | none | `capabilities.get`, sanitised |
| `app_events` | a `tauri::ipc::Channel` and an optional `{after_seq, epoch}` | sanitised events and snapshots; cancels any earlier subscription; ends on window close |
| `app_tasks` | none | `task.list`, sanitised |
| `app_task` | `task_id` (identifier rule) | `task.get`, sanitised |

CR-03 step 2 proposed one generic `app_api_call` with a name allowlist. Typed commands are used instead: no argument can carry a method name. The names are listed once, in `build.rs` (`tauri_build::Attributes::new().app_manifest(AppManifest::new().commands(&[...]))`), so each command needs an explicit permission, and the `invoke_handler` registers exactly these five. A test compares the two lists.

### Capabilities (Tauri ACL)

One capability file, for the window labelled `main` only, granting only the five generated `allow-app-*` permissions. No `core:default`, no `core:window:*`, `core:webview:*`, `core:event:*`, `core:path:*` or `core:app:*` permission, no `remote` section, no platform-wide wildcard. No plugin is registered: no shell, fs, http, dialog, opener, process, updater, clipboard, notification, global-shortcut, deep-link, single-instance or store plugin. `deny.toml` bans every `tauri-plugin-*` crate (below).

### Content Security Policy and configuration

Set in `tauri.conf.json` `app.security.csp`, so Tauri adds its own script hashes and nonces at build time:

```
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src ipc: https://ipc.localhost; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'
```

No `'unsafe-inline'`, `'unsafe-eval'`, `'wasm-unsafe-eval'`, `ws:`, `wss:`, `http:` or `https:` source. Also in the configuration, each asserted by the A2 configuration test: `dangerousDisableAssetCspModification: false`; `assetProtocol.enable: false` (no `asset:` file access); `freezePrototype: true`; the `main` window declared with `useHttpsScheme: true`, so its origin is `https://tauri.localhost` on Windows; `dragDropEnabled: false`; `withGlobalTauri: true`; no `devUrl`; `bundle.active: false`.

**IPC origin.** With `useHttpsScheme: true` the page's origin is `https://tauri.localhost` and Tauri's custom-protocol IPC on Windows is expected at `https://ipc.localhost`, so `connect-src` names `ipc:` and `https://ipc.localhost`. A plain `http://ipc.localhost` would be blocked by this CSP, and Tauri would then fall back to `postMessage` IPC. A2 may replace the scheme of `ipc.localhost` on recorded evidence; it adds no other source. A2 adds a native test that every command call goes through the custom protocol and none through `postMessage`. The count is taken **on the Rust side only**; no probe is compiled into the page. During the hidden-create step the shell registers its own WebView2 `WebMessageReceived` handler, which counts every web message (Tauri's `postMessage` fallback arrives there) and answers none, and each command handler counts the calls it serves. On exit the shell writes one line, `SG119-IPC commands=<n> web_messages=<m>`; the native test requires `n` above zero and `m` equal to zero. If A2's evidence shows Tauri never needs web messages on Windows, it also sets `IsWebMessageEnabled` false, so the fallback cannot exist.

### No remote content, no navigation, no downloads

- Assets are embedded at compile time (`custom-protocol` feature, `frontendDist` pointing at the compiled front end). There is no `devUrl`, no dev server and no listener of any kind.
- **Navigation.** The window's `on_navigation` handler parses each URL and allows it only if its scheme, host and port equal the asset origin exactly (`https`, `tauri.localhost`, default port). Prefix or substring matches are not used, so `https://tauri.localhost.evil/`, `http://tauri.localhost/`, `https://tauri.localhost:8443/`, `https://user@tauri.localhost.evil/` and `ipc.localhost` as a navigation target are refused, as are `https:`, `http://127.0.0.1`, `file:`, `data:`, `blob:` and `javascript:` URLs.
- **New windows.** `on_new_window` answers deny. If the pinned Tauri lacks it, WebView2's `NewWindowRequested` handler, registered through the platform web view handle, marks every request handled with no window. Before A2 merges, it records in this packet and in the spec which of the two paths it used, and the behaviour tests (`window.open(...)` from the page opens no window; a link with `target="_blank"` opens none) run on that chosen path.
- **Downloads.** `on_download` refuses every download.
- `withGlobalTauri: true` exposes `window.__TAURI__.core.invoke` so no `@tauri-apps/api` npm package is needed. The page is the only content the view ever loads.

### Web view hardening (WebView2)

- **Devtools off three ways:** the `devtools` Cargo feature is not enabled, the window builder calls `.devtools(false)` explicitly, and the WebView2 setting `AreDevToolsEnabled` is false.
- **Order of creation.** `with_webview` runs only after the web view exists, so the window is built with `visible(false)`, then the WebView2 settings and the `NewWindowRequested` and download handlers are applied, then each setting is read back and asserted (a mismatch closes the window with a stated reason), then the page is reloaded so nothing loaded before the settings survives, and only then is the window shown. A2 tests the readback and that the first visible paint follows the reload.
- **Settings through the platform web view handle** (`with_webview` → `ICoreWebView2Settings`), applied in that order: `AreDefaultContextMenusEnabled` false; `AreBrowserAcceleratorKeysEnabled` false (no F12, Ctrl+Shift+I, Ctrl+P, Ctrl+F, Ctrl+R, F5 or similar browser keys); `IsStatusBarEnabled` false; `IsGeneralAutofillEnabled` false; `IsPasswordAutosaveEnabled` false; `AreHostObjectsAllowed` false; `IsBuiltInErrorPageEnabled` false. Web messages stay enabled only if Tauri's IPC needs them on Windows, which A2 records; either way the Rust-side `WebMessageReceived` counter above stays registered. Calling these makes `webview2-com` a direct dependency at exactly the version Tauri already resolves, so it adds no download.
- **Browser arguments, explicit.** The window sets `additional_browser_args` itself, which replaces Tauri's defaults, to exactly `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`. Justification: these are Tauri's defaults; `msSmartScreenProtection` stops URL reputation lookups to Microsoft (the view only loads embedded assets, so they protect nothing), and `msWebOOUI` and `msPdfOOUI` keep Edge's out-of-process UI surfaces out of the view. No other argument, and never a remote-debugging or logging argument.
- **Environment overrides.** WebView2 honours `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER`, `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`, `WEBVIEW2_USER_DATA_FOLDER`, `WEBVIEW2_RELEASE_CHANNEL_PREFERENCE` and the same through policy registry keys. The Rust `main` refuses to start, with a stated reason, when any environment variable whose name starts with `WEBVIEW2_` **compared case-insensitively** is set (Windows environment names are case-insensitive). A same-user process can still change the user's registry; that is the same residual as squatting the pipe (below), recorded rather than solved.
- **User data folder.** Set explicitly under the Control Room's own per-user directory, outside orceld's state root. It holds the view's cache only, no Orcel state. `orcel uninstall --purge-data` is not extended in this grain (a known limit).
- **A5 checks** (UI Automation on Windows): F12, Ctrl+Shift+I, Ctrl+P and a right-click on the page each produce no new window, no devtools, no print dialog and no context menu.

### Untrusted strings in the front end

The front end renders every field with `textContent`, never `innerHTML`, `insertAdjacentHTML`, `document.write`, `eval` or `Function`; a static check in the front end's tests fails on any of them or on an inline event handler.

### The renderer cannot reach orceld

On Windows, the WebView2 renderer runs in Chromium's sandbox below Medium integrity, and the pipe's `ME` mandatory label refuses it, so page script, even a compromised renderer, can reach orceld only through the five commands. This matters beyond reads: `task.stop`'s exception to the first-party code rule (`ORCEL_APP_API_1.md` section 2) rests on no confined process reaching the endpoint. Slice A5 records native evidence.

### Accepted residuals (same as the WPF preview)

The pipe name is predictable: another same-user process at Medium integrity could serve it first and show invented state. Nothing it shows can act, because the Control Room sends nothing that acts.

The mutex name is predictable too: another process could create `Local\orcel-control-room-<SID>` first. Another account's mutex is refused with `ERROR_ACCESS_DENIED` and reported as such; a same-user process holding it only keeps the window from opening (denial of a viewer, no authority).

## Slice A3 as implemented

Branch `sg119/a3-commands` (2026-11-16), from `sg119/a2-shell` (PR #777, under review). It adds the five read-only commands over the A1 client and their ACL tests, and nothing of A4: the page is still A2's static page. **No download and no lock change:** `Cargo.lock` is A2's, byte for byte (SHA-256 `9cb466475467c9e1b9756838c89eb86c52345e455ea6a795d50c8ed7af07c38c`); every build and test ran `--locked`.

### What it adds

- **`src/commands.rs`**: `app_status`, `app_capabilities`, `app_events`, `app_tasks` and `app_task`, registered by `generate_handler!` and nothing else. Each calls the A1 client (`status.get`, `capabilities.get`, `events.subscribe`, `task.list`, `task.get`) and returns only the sanitiser's types, re-serialized from Rust. The commands are `async` and run the client's blocking reads on Tauri's blocking pool, so the window never waits on orceld.
- **Permissions.** `build.rs` names exactly the five in `tauri_build::AppManifest::commands`; tauri-build generates `allow-<command>` and `deny-<command>` for each under `src-tauri/permissions/autogenerated/` on every build (ignored by git, like `gen/`; the ACL test asserts their content and that no hand-written permission file exists). `capabilities/main.json` grants exactly `allow-app-status`, `allow-app-capabilities`, `allow-app-events`, `allow-app-tasks` and `allow-app-task` to the `main` window, still with no core permission, no `remote` section and no plugin. With an app manifest, Tauri's ACL refuses any app command a capability does not grant before it reaches the invoke handler.
- **Arguments, typed and bounded.** Each command reads its arguments itself from the request body, which must be a JSON object with no key beyond its own: none for `app_status`, `app_capabilities` and `app_tasks`; `task_id` (identifier rule, through the client's `TaskId`) for `app_task`; `channel` (a `tauri::ipc::Channel`) and an optional `from: {after_seq, epoch}` (exactly those two keys, the epoch in orceld's format, through the client's `Cursor`) for `app_events`. Tauri itself ignores extra keys, which is why the commands parse the body. An extra argument, a raw body, a malformed `task_id`, channel or cursor is refused before anything is sent to orceld.
- **Errors, typed and non-leaking.** A `CommandError` enum reaches the page as `{"error": "<kind>"}` (`unavailable` with a `reason` of `not_running`, `no_free_instance`, `timed_out`, `connection_lost` or `no_location`; `not_yours`; `incompatible`; `busy`; `refused` with orceld's error `code` only, `[A-Z_]` at most 32 as the client keeps it; `frame_too_large`; `protocol`; `task_withheld`; `invalid_arguments`; `invalid_task_id`; `internal`). No orceld message, OS error code, path, pid or SID is carried.
- **Events.** `app_events` goes through the client's `Window`: a new call ends the previous subscription (its orceld connection closed, its thread joined) before it opens one; the client's bounded queue of 256 and its gap and resubscribe rules apply unchanged. A pump thread sends each stream item on the channel exactly as the client serializes it (`{"type": "event" | "withheld" | "cleared" | "gap" | "unavailable" | "not_yours" | "incompatible", ...}`), then `{"type": "ended"}` when the subscription ends. Closing the `main` window (`CloseRequested` or `Destroyed`) or the app's exit ends the subscription. The window uses at most two of orceld's client slots: one subscription and one serialized request.
- **Counting.** `SG119-IPC commands=<n>` now counts the calls the five handlers served (a call the ACL refuses never reaches them); `web_messages` is unchanged.

### Security judge fixes (2026-11-16, after merging A2's fixes at `d2af246f`)

1. **Low, free text in a stream item.** The A1 client built `StreamItem::Unavailable { reason }` from its error's English `Display` text, which could carry an OS error code.
