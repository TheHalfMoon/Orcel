# Trusted security architecture for the cross-platform plan

Status: ADOPTED planning direction (founder, 2026-10-18; `docs/orcel/grants/2026-10-18-founder-attestation.md`), authored by Fable. Living threat baseline remains `docs/security/THREAT_MODEL.md` and `docs/orcel/SECURITY_THREAT_MODEL.md`; this file is the delta introduced by the integrations in this package. Nothing here weakens an existing control.

## 1. Non-negotiable rule

**The AI proposes. Orcel authorizes. Orcel executes. Orcel verifies.** For every imported donor unit:

1. It runs inside an Orcel-owned process with no listener and a closed request vocabulary.
2. It never decides policy, never presents or answers an approval, never mints identity, leases or tokens.
3. It never evaluates caller-, model- or page-supplied script.
4. It never opens a second channel to the browser, the desktop or the network.
5. It never retries a mutation; unknown outcomes go to the journal and reconciliation.
6. Its telemetry, auto-update and download paths are removed or compiled out.
7. Its notices and provenance travel with it.

A donor unit that cannot meet these is not imported, whatever its license.

## 2. Privilege boundaries (unchanged, extended to new OSes)

| Boundary | Windows | macOS | Linux |
|---|---|---|---|
| User ↔ Orcel approvals | `MessageBoxW` system-modal, Hello | CFUserNotification, LocalAuthentication helper (code-signature checked) | GTK4 helper, polkit `auth_self` |
| orceld ↔ hosts | inherited pipes | inherited pipes | inherited pipes |
| orceld ↔ local UI | named pipe + DACL | Unix socket 0700 + peer creds | Unix socket 0700 + `SO_PEERCRED` |
| orceld ↔ remote | relay + OAuth + device identity | same | same |
| Host ↔ target app | UIA | AX (TCC Accessibility), ScreenCaptureKit (TCC Screen Recording) | AT-SPI bus, X11, Wayland portals |
| Browser engine ↔ network | resolver rules + no-route proxy | resolver rules + host-owned sink | resolver rules + host-owned sink |

### XP-09 manual live check (macOS)

CI cannot answer a dialog, so the approving path is checked by hand on a Mac at the keyboard, outside CI, in a GUI login session with Touch ID or a login password:

1. `ORCEL_LIVE_APPROVAL_DIALOG=1 ORCEL_LIVE_APPROVAL_EXPECT=approve cargo test -p orcel-approval xp09_live -- --nocapture --test-threads=1`. A caution alert titled "Orcel approval SOFT" shows the request; Deny is the default button. Click Approve. Then the LocalAuthentication prompt names the STRONG request; confirm with Touch ID or the password. The test passes only if both are approved.
2. Run it again with `ORCEL_LIVE_APPROVAL_EXPECT=deny`: press Return on the alert (Deny) and cancel the LocalAuthentication prompt. The test passes only if both are refused.
3. Over SSH to the same Mac, the same commands with `approve` fail (no GUI session); `cargo test -p orcel-approval xp09_macos_headless` passes there and nothing is shown.

Record the macOS version, hardware, and observed outcome as GitHub evidence (issue #362 and PR #361).

### XP-07 exact-window capture: rules and manual live check (macOS)

The host captures one bound window and nothing else (`apps/orcel-native-host/src/capture.rs`, vendored patch P-08):

- No display, monitor or region capture is reachable: the request has no such field, no Cua capture tool is registered, and a host test fails if host code names Cua's display, root-region, probe-frame or Wayland output capture.
- Protected surfaces are refused before any pixel is read: Orcel's approval, trust and revoke windows, lock screens, and authentication and password dialogs (`SecurityAgent`, `coreautha`, `AuthorizationHost`, `loginwindow`, `ScreenSaverEngine`, the LocalAuthentication UI, and the system alert agents `UserNotificationCenter` (which draws the XP-09 SOFT approval as an untitled `CFUserNotification` alert, so it is refused by owner, never by title), `universalAccessAuthWarn` and `CoreServicesUIAgent`; polkit agents, pinentry, ssh-askpass, the GNOME keyring prompter, KWallet and screen lockers on Linux). The host's markers are the kernel's `is_protected_window` lists, and a host test requires them to stay equal.
- Minimized, hidden and off-Space windows are refused as unavailable and are never restored, raised or focused. On X11 a covered or clipped window is refused too, because X11 capture reads the screen's copy of the window. Residual risk: a window that covers the target only between the check before the read and the check after it (about 26 ms) can reach the frame. A server grab cannot close the gap, because Cua reads on its own X connection and would stall behind a grab held by the host. ScreenCaptureKit's window filter reads the window's own buffer.
- Frames are at most 7680x4320 and 8 MiB of RGBA, are never scaled down, and carry no pointer.
- In process only. The `screencapture` CLI, SkyLight and ImageMagick fallbacks are not used, so no file is written and no subprocess is started.
- Never a prompt (P-04). Capture needs Screen Recording, read without prompting. From macOS 15, the first capture by an app raises replayd's "bypass the private window picker" alert. It finds that app with libSystem's `responsibility_get_pid_responsible_for_pid`, then reads `~/Library/Group Containers/group.com.apple.replayd/ScreenCaptureApprovals.plist`. Anything unknown counts as missing, so capture is unavailable with `permission_missing` and a reason. The hello reports `permissions.direct_capture_consent`. Until XP-16 gives the host its own signed bundle, the responsible app is the terminal (or the app that starts orceld).

### XP-12 raw input: rules, approval status and manual live check

XP-12 adds bounded pointer, scroll and key input on macOS and Linux X11, the highest-risk native capability. It is judged adversarially; these are the rules and where each is enforced (the spec is `ORCEL_COMPUTER_HOST_2.md`, section 5.4).

- The kernel admits five operations (`input_click`, `input_drag`, `input_scroll`, `input_type_text`, `input_key`) and no others; a hover (`input_move`), a key chord (`input_hotkey`) and `window_action` stay capped to `observation_only` whatever the host advertises.
- Approval. orceld requests and consumes an approval for the exact request, then arms it in the adapter on the window binding (pid, start generation, nonce) and the SHA-256 digest of the exact input. The adapter spends it on the first input, win or lose: a replay, another input, another window or a replaced window is refused with no frame. The host cannot see an approval and does not rely on one.
- The target. Coordinates are window-relative points; a point outside the live frame is refused, never clamped. Before every delivery unit (a click, a drag, a scroll, a key, or eight typed characters) the worker proves the binding, the owner, that the window is not protected, is on screen, has not moved or resized, is not covered and that the person has not touched the machine since the tick the kernel read (30 ms of clock jitter allowed, not more). The person must also have been quiet for 250 ms before the first unit, because the kernel reads its baseline right after the Approve click; a person still typing or moving then cancels the input, and an unreadable clock refuses it. Between units the tick is read again. On macOS it must not have moved at all (up to the reader's 1 ms rounding), since events posted to one process do not move the session clock. On X11, where the server counts the host's events as input, it may also lie inside the unit's delivery call (20 ms reading slack each side, the 40 ms settle wait excluded). The tick is also read once more immediately before each delivery call, after the gate (which for a keyboard unit re-reads the tree), so a keystroke made during that read cannot be masked by the unit's own X11 event. A person's keystrokes are never adopted as the new baseline: they cancel the rest. `deliver_sequence` holds this logic, and its worker tests drive it with a fake runtime and a fake tick source (#404). Typed text and keys also re-read the window's accessibility tree before every unit, and a window whose tree cannot be read (Tk, a bare Xlib or SDL program) takes no typed input. A failure before the first unit sends nothing; after an earlier unit it is `outcome_unknown` and is not repeated.
- Protected surfaces are owner-based, as in XP-07 and XP-11: Orcel's own approval windows (the XP-10 helper, the XP-09 alert), OS authentication and lock agents and any `orcel*` executable take no input. A window whose tree shows a secure text field takes none either.
- No system shortcut. Only plain navigation, editing and activation keys and single letters and digits are typed; no modifier, chord or function key. Typed text is at most 256 characters with no control character; a request is at most 3 clicks, one 500 ms drag, 20 scroll lines or one key, and raw input is paced to one sequence per 250 ms per adapter.
- The wrong application. Found by the XP-12 conformance run on X11: Cua resolved a window whose process draws no accessibility tree to a different application that shared the process name, and a pixel click at a point of the approved window fired a check box of that other application. P-10 (PATCHES.md) accepts a name match only for an ancestor or descendant of the target. The regression is `conformance_native.rs`, whose GTK3 harness and Tk probe are both `python3`.
- No new prompt (P-04): a missing Accessibility, Screen Recording or capture-consent grant is `unavailable` with `permission_missing`; the host never asks.
- Wayland: unavailable. No GNOME helper or KDE helper is installed or vendored (T-CUA-18, T-CUA-19 stay deferred); installing a Shell extension is an interactive, user-visible step, and KWin documents a focus race.
- No network and no listener are added; `unsafe` is confined to two FFI calls in `input.rs::tick` (CoreGraphics idle time and `clock_gettime`), each with a SAFETY comment.

Residual and follow-ups, stated plainly: (1) S-05: the SkyLight input SPI is a capability (P-11, off by default); with it off the public route is used, and neither route has been exercised on a Mac. (2) On X11, a touch made while a unit's delivery call is running (plus 20 ms of reading slack either side) cannot be told from the host's own events, because they move the same clock. A touch during the 40 ms settle wait is outside that window and cancels the rest (#404). On macOS no touch is explained, because the host's events do not move the clock; if a macOS release ever counted `CGEventPostToPid` events, multi-unit input would cancel after its first unit (`outcome_unknown`), which fails closed. That is part of the macOS manual check. (3) A drag is one vendored call of 500 ms; the window is proved before it, not during it. (3b) X11 race: the gate proves the window and the point immediately before delivery, but the pointer route (uinput, or XTest) addresses screen coordinates, so a window that is raised, moved or replaced in the microseconds between the gate and the event can receive it; the pid and frame checks narrow this to that interval and the owner generation is read last, but it is not closed. (3a) Keyboard input on Linux X11 needs Cua's virtual master keyboard (Xorg and a writable `/dev/uinput`); Linux CI runs Xvfb, which cannot have it, so there the hello says `input_type_text` and `input_key` are unavailable and the conformance and live cells for them are typed skips that send their frame and require the refusal. Pointer delivery to a Tk probe is measured in CI, and the whole keyboard path was exercised only up to that refusal; typing and a key on Xorg with uinput, and every macOS delivery, are manual checks that were NOT RUN for this task. (4) The shared web page does not expose its controls' geometry to the host, so its px conformance cells are skips (`no-geometry`) and raw input is measured on the probe instead.
