The package says the People First identity is "the founder-approved v5 already rolled out in PR #811". As of this
assessment PR #811 (`brand/people-first`) is **open and unmerged**; main still ships v4 (the Night Window). So:

- The tokens do assume #811's brand. `brand.*` in `orcel.tokens.json` (vermilion `#DB2532`, ink `#141414`, navy

  colours #811's SVGs use.

  (different `viewBox`, size attributes and accessible names; every compared pair has a different SHA-256). The
  package's names (`orcel-mark-red.svg`, `product-icon-agent.svg`, ...) differ from #811's (`orcel-mark-red.svg`,

Mechanical packaging decisions (no design content changed):

- **Folder name.** The contract requires the folder to equal the manifest's semantic version, so the package lives
  in `design/handoff/1.0.0/`, not `design/handoff/v1/`. A folder named `v1` fails `MANIFEST_SCHEMA` (version
  pattern) and `MANIFEST_VERSION`.
- **Status.** The schema allows `draft`, `review`, `approved`, `withdrawn`; "proposed" is not a value. `review` is
  the schema's word for a proposed package; `identity.notes` says it is proposed and unapproved.
- **Component split.** One file per component, as the contract asks. The general "Rules that apply to every
  component" section is not a component and was not packaged; the Design session should fold it into the specs.
  `states` in the manifest lists only the states each spec's own **States** line names; specs without one are
  recorded as `["default"]` and fail `COMPONENT_STATES`, which is accurate. Surfaces: `navigation-web-header` is
  `website`, `navigation-app-sidebar` is `control-room`, the rest `shared`.
- **Logo kinds and grounds.** `lockup`, `wordmark`, `mark` from the file names; product icons as `app-tile` on `any`
  ground (they carry their own tile); `-white` files `dark`, `-ink` and `-red` files `light`; UI icons `ui-icon` on
  `any` (they draw in `currentColor`). The Design session should confirm the grounds.
- **Line endings.** `.gitattributes` already marks `design/handoff/**` as `-text`; the copied files are LF and
  unchanged, so the hashes hold.

Left out, on purpose:

- `tokens/orcel.css` and `tokens/orcel.tailwind.css`: generated files; the contract has one token source and
  engineering's generator writes the CSS.
- `boards/` (canvas HTML), `source/` (builders, `.pyc` files), `handoff/*.md` other than the component specs: the
  contract has no place for them, and boards are never an engineering source (`CONTRACT.md` section 5).
- `renders/`: about 66 MB (30 MB in `final/` alone). The contract's `screens/` is optional in the schema, and committing tens
  of megabytes of PNG to a public repository is not reasonable. The Design session should deliver a curated set
  (section 2.3).
- `source/assets/illus/*`, `source/assets/char/*`, `source/assets/fig/*`, and the 18 browser-only icons in
  `source/browser_parts.py`: used by the boards but not delivered as assets. They should move into `assets/`.
- No fonts were committed; none were delivered.

## 3. Controls that need authority paths

Today's Control Room is read-only on purpose. Its client sends only `status.get`, `capabilities.get` and
`events.subscribe`, refuses every other method before writing, and `no-authority.test.ts` proves there is no approval,
submit, cancel or stop path (`apps/orcel-control-room/README.md`). orceld's app API (`ORCEL_APP_API_1.md` section 4)
serves `status.get`, `capabilities.get`, `events.subscribe`, `task.list`, `task.get`, `approval.history`,
`task.stop` and `clients.list`, reserves `devices.list`, and answers `UNKNOWN_METHOD` to anything that would submit,
approve, mint, cancel or write. The first state-changing method needs a first-party code identity check
(the only exception is `task.stop`, founder decision #446, because it can only reduce authority). Commit approvals
are raised by orceld in the operating system's own prompt.

The Tauri shell can call exactly five commands (`app_status`, `app_capabilities`, `app_events`, `app_tasks`,
`app_task`; `src-tauri/src/commands.rs`, `capabilities/main.json`), allows no Tauri plugin (`src-tauri/deny.toml`),
and `src-tauri/tests/acl.rs` checks that it refuses `task_stop`. SG-000119 records the window as a viewer with no
authority delta. So **no designed control that changes state is reachable from the Control Room today**, including
the one that exists in orceld (`task.stop`).

### 3.2 Read-only screens also need new read methods

Even the "read-only" parts of the design need methods the Control Room cannot call today: run lists and run detail
(`task.list`/`task.get` exist in orceld; the TS client refuses them, while the Rust shell exposes them, an
inconsistency to fix first), approval history (`approval.history` exists, not exposed), pending approvals (absent),
leases (`browser.lease.list` exists as an orceld local op, not in the app API), devices (`devices.list` reserved),
connected clients (`clients.list` exists, not exposed), audit log (absent), live session thumbnails and Shadow live
view (absent; a frame stream is new data leaving orceld). Each read method is a protocol change with its own tests.

## 4. Conflicts with security rules

Repository rules that apply: orceld is the only authority; the Control Room is a viewer; approvals stay with the
operating system's presence surfaces and the UI only displays what is waiting (`ORCEL_APP_API_1.md`, SG-000119);
approval prompts are not design surfaces and no app UI may imitate them (`CONTRACT.md` section 1); a lease's consent
is the Yes on service-rendered text, and Windows Hello is presence, not consent (`crates/orcel-authority/src/core.rs`);
Orcel never solves a CAPTCHA, never types a password and never enters a one-time code (`browser_broker.rs`), and
payments are high-impact and outside any lease (SG-000135).

## 5. What is compatible as drawn

- The colour rule ("red is you, blue is them, navy is Shadow Mode"), the focus ring (2 px, `border.focus`, never red),
  outlined-only destructive actions, verb-first copy and status honesty (Preview pills, macOS "Coming next",
  SmartScreen notice) fit the repository's direction.
- Token contrast passes the contract's built-in pairs under the mapping in section 2.2.
- The Control Room's strict CSP (`style-src 'self'`, `font-src 'self'`, `img-src 'self'`) can hold: generated token
  CSS and local SVG icons are static files; fonts, if adopted, must be bundled locally (the package says so too).
- The website is a static export; tokens, pages and icons can be integrated without any authority change.
- Read-only Control Room views (status, timeline, run list, approval history, connected clients) can be built from
  methods orceld already serves, once each is exposed through the reviewed read-only path.
